# (가칭) 로컬 AI 보안·비용 게이트웨이

> API 주소 한 줄만 바꾸면 기존 AI 서비스에 개인정보 보호와 토큰 절약이 붙는 로컬 게이트웨이

인공지능프로젝트 수업 개별 프로젝트 · 학과 생성형 AI 경진대회 출품작 (개발 중)

## 왜 필요한가

- 생성형 AI를 쓰면 개인정보·기밀이 그대로 외부 AI 서버로 전송된다.
- 쉬운 요청까지 비싼 고성능 모델로 보내 비용과 지연이 낭비된다.
- 로컬 AI 보안 도구는 설치·설정이 어려워 중소기업이 도입하기 힘들다.

## 세 가지 강점

| 강점 | 내용 |
|---|---|
| 보안 | 민감정보 원본은 외부로 나가지 않는다. 판단도 로컬에서 한다. |
| 토큰 절약 | 로컬 판단 모델이 요청을 분류해 필요한 만큼의 모델에만 보낸다. |
| 간편함 | 무거운 로컬 LLM 없이 가벼운 판단 모델만 로컬에서 실행한다. 설치 스크립트 하나, 설정은 보안 수준 하나. |

## 동작 방식

```
기존 AI 서비스 (API 주소만 게이트웨이로 변경)
   ↓
① 민감정보 가명화 (코드: 정규식·사용자 사전)   "김민수(010-1234-5678)" → "[고객1]([전화번호1])"
   ↓
② 판단 (Laya, 로컬)   민감정보·기밀·원본 필요 여부, 난이도, 의도, 위험·인젝션
   ↓
③ 경로 선택   템플릿 응답 / 저렴한 모델 / 고성능 모델 / 차단 + 안내
   ↓
④ 답변 생성 (LLM)   가명화된 텍스트만 외부로 전송
   ↓
⑤ 복원 (코드)   답변 속 가명 토큰을 원래 값으로 되돌려 반환
```

**판단은 Laya, 생성은 LLM, 마스킹은 코드.** 원본과 가명의 대응표는 요청 처리 중 메모리에만 두고, 로그에는 가명화된 텍스트만 남긴다.

### 보안 수준

| 수준 | 동작 |
|---|---|
| 기본 | 가명화 → API 전송 → 로컬 복원. 원본 값이 필요한 요청은 안내 후 차단 |
| 엄격 | 기본 + 기밀로 판단되거나 이름·주소가 의심되면 차단 |
| 완전 로컬 (옵션) | 민감한 요청은 외부로 보내지 않고 로컬 LLM이 처리 |

## 설치

> M4(11/12~11/14)에 설치 스크립트와 함께 작성 예정

## 사용법 (M1 구현 예정)

기존 서비스의 API 주소만 게이트웨이로 바꾼다.

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="...")
```

## 설정

| 파일 | 내용 |
|---|---|
| `config.yaml` | 보안 수준, 판단 엔진 주소·모델, 신뢰도 기준, LLM 모델. 비밀값 없음 |
| `.env` | API 키 등 비밀값. `.env.example`을 복사해서 만든다. 커밋하지 않는다 |

## 저장소 구조

| 경로 | 역할 |
|---|---|
| `gateway/api/` | OpenAI 호환 엔드포인트 (`/v1/chat/completions`) |
| `gateway/masking/` | 정규식·사용자 사전 기반 민감정보 감지, 가명화, 복원 |
| `gateway/decision/` | 판단 엔진(`/v1/systemone` 형식) 클라이언트, 판단 질문 정의 |
| `gateway/routing/` | 보안 수준·판단 결과·신뢰도로 처리 경로 결정 |
| `gateway/llm/` | 저렴한 모델·고성능 모델 API 클라이언트 |
| `gateway/storage/` | SQLite 요청 로그 (민감정보 원본 미저장) |
| `admin/` | Streamlit 관리·데모 화면 |
| `bench/` | 벤치마크 실행기 |
| `finetune/` | (조건부) 한국어 파인튜닝 |
| `data/` | 테스트셋 (이름·번호는 전부 가상 값) |
| `scripts/` | 설치 스크립트 |
| `tests/` | pytest |
| `docs/` | 설계 결정, AI 활용 기록, 발표 자료 |
