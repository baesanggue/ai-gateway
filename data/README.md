# 테스트셋 (`testset.csv`)

벤치마크(판단 정확도, 마스킹 재현율·정밀도, 비용)에 쓰는 한국어 요청 100개. 쇼핑몰 고객센터와 사내 업무 시나리오.

> **이름·전화번호·이메일·카드·계좌·주민번호·주소는 전부 가상 값이다.**
> - 전화번호: `010-0xxx-xxxx`(미사용 대역) 위주. 시연용 `010-1234-5678`만 예외
> - 이메일: 예시용 예약 도메인 `example.com`, `example.co.kr`
> - 카드번호: 결제사가 공개한 테스트 번호
> - 주민번호: 검증 숫자가 틀리게 만든 번호 (실제로 발급될 수 없는 값)
> - 주소: 실제 구 이름 + 가상 도로명(`가상로`, `샘플로`, `예시대로`)

## 구성

| id 범위 | 범주 | 개수 |
|---|---|---|
| T001–T030 | 단순 문의 (T001–T015 템플릿, T016–T030 저렴한 모델) | 30 |
| T031–T050 | 복잡 문의 | 20 |
| T051–T070 | 민감정보 포함, 가명화로 처리 가능 | 20 |
| T071–T080 | 원본 값이 있어야 답할 수 있음 | 10 |
| T081–T100 | 기밀(T081–T087) · 위험·인젝션(T088–T094) · 무관(T095–T100) | 20 |

## 컬럼

| 컬럼 | 값 | 뜻 |
|---|---|---|
| `id` | `T001`~`T100` | |
| `text` | 문자열 | 사용자 요청 원문 |
| `expected_route` | `template` / `cheap` / `premium` / `block` | **기본 보안 수준**에서 기대하는 경로 |
| `has_pii` | 0 / 1 | 민감정보 포함 여부 |
| `pii_types` | `name`, `phone`, `email`, `rrn`, `card`, `account`, `address`를 `\|`로 연결 | 포함된 민감정보 유형 |
| `needs_raw_value` | 0 / 1 | 답하려면 민감정보의 실제 값이 필요한가 |
| `is_confidential` | 0 / 1 | 가명화로도 부족한 사내 기밀인가 |
| `is_risky` | 0 / 1 | 위험 요청 또는 프롬프트 인젝션인가 |

- **엄격 수준**의 기대 경로는 따로 적지 않고 규칙으로 계산한다: `is_confidential=1`이거나 `pii_types`에 정규식으로 못 잡는 `address`가 있으면 `block`.
- **무관** 요청은 별도 컬럼 없이 `expected_route=block`이면서 다른 플래그가 모두 0인 행이다.
- 이름은 사용자 사전에 등록된 고객·직원명으로 가정한다. 주문번호·운송장번호(T003, T009)는 민감정보가 아니다. 숫자열을 잘못 잡는지 보는 정밀도 확인용이다.

## 파일 형식

- UTF-8 **BOM 포함**. Excel에서 열어도 한글이 깨지지 않는다.
- Python에서는 `encoding="utf-8-sig"`로 읽는다.
- Excel로 수정하면 저장할 때 형식을 **"CSV UTF-8(쉼표로 분리)"**로 고른다.
- GitHub 웹에서 열면 표로 보인다.

## 열린 질문 (M2에서 결정, 결정되면 라벨 수정)

1. **기본 수준에서, 정규식으로 못 잡은 주소·이름을 Laya가 감지하면?** Laya는 위치를 짚지 못하므로 코드가 가릴 수 없다. 그대로 보내면 원본이 외부로 나간다. 현재 라벨(T054, T060, T065, T070)은 CLAUDE.md의 기본 수준 정의대로 `cheap`/`premium`이다.
2. **기본 수준에서 기밀 요청(T081–T087)을 외부로 보내는가?** CLAUDE.md상 기밀 차단은 엄격 수준에만 있어서 현재 라벨은 `cheap`/`premium`이다.
