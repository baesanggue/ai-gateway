## 결론

**`d1:3b`만 한국어 판단을 보정 없이 바로 쓸 수 있는 수준이다.** 이 표본에서는 파인튜닝·보정이 필요 없었다. 남은 문제는 CPU 속도다.

| 판단 (기본 기준값) | `d1:3b` | `laya:multilingual` |
|---|---|---|
| 민감정보: '예' 재현율 / 오탐 | **8/8 · 0/12** | 8/8 · 9/12 (noul) |
| 원본 값 필요 | 2/4 · 0/16 | 4/4 · 9/16 (noul) |
| 기밀 / 위험 | 1/1 · 2/2, 오탐 0 | 0/1 · 1/2, 오탐 다수 |
| 난이도 (score) | **0.92** | 0.62 |
| 의도 | 0.78 (FAQ 2/2 · 무관 1/1 · 업무 11/15) | 0.17 |
| CPU 지연 (질문 11개) | 10.0초 (질문당 0.91초) | 0.8초 (질문당 0.07초) |
| GPU 지연 (Vulkan, RTX 4080) | **0.78초** | — |
| 메모리 | 2.9GB (Q8_0) | 1.9GB |

- `d1:3b`의 CPU와 GPU 답은 220개 중 219개가 같았다 (속도만 다르다).
- 질문을 5개로 줄이면 이 PC의 CPU에서 약 4.6초로 예상된다. 잠정 기준인 "CPU에서 질문 5개 2초 이내"를 넘는다.

## 선택지

| | 방법 | 판단 품질 | 지연 | 일정 위험 |
|---|---|---|---|---|
| **1** | `d1:3b` 채택 + 질문을 2~3개로 통합 | 바로 사용 가능 | CPU 약 2~3초(추정), GPU 1초 미만 | 낮음 |
| 2 | `laya:multilingual` 유지 + 파인튜닝 | 파인튜닝 결과에 달림 | CPU 1초 미만 | 높음 (학습 데이터·학습·서빙 경로 미확인) |
| 3 | `d3:edge` + 보정 (민감정보·기밀만) + 라우팅은 다른 방법 | 일부만 | CPU 1~2초 | 중간 |

**권장: 1.**
- 모델 교체는 `config.yaml` 한 줄이고 파인튜닝이 필요 없어 일정 위험이 가장 작다.
- GPU가 있으면 Ollaya가 자동으로 쓰므로(`OLLAYA_DEVICE=auto`) 시연 PC에서는 1초 미만이다.
- 10/28 B 단계(질문 개선)에서 질문을 통합해 CPU 지연을 실측한다. 예: 라우팅 1개(FAQ / 단순 업무 / 복잡 업무 / 무관), 위험 1개(정상 / 원본 필요 / 기밀 / 위험·인젝션), 정규식이 놓친 이름·주소 1개.
- `laya` + 파인튜닝은 "CPU에서 더 가볍게" 만드는 M6 개선안으로 남긴다.

## 결정할 것 · 주의

- **"가벼움"의 정의**: `d1:3b`는 잠정 기준(CPU 질문 5개 2초)을 넘는다. 다음처럼 바꿀지 결정해야 한다(사용자 결정): "판단 전용 3B 이하 모델, 메모리 4GB 이하, GPU(내장 GPU 포함)가 있으면 1초 미만, CPU만 있으면 수 초". 생성형 로컬 LLM(7B 이상)을 넣지 않는다는 원칙 P3는 그대로 지켜진다.
- **라이선스**: `d1`은 LFM Open License v1.0이다. 연 매출 1,000만 달러 이상인 조직의 상업 사용은 허용되지 않는다. 수업 프로젝트와 중소기업 타깃에는 문제없지만 README에 적어야 한다.
- **확인하지 못한 것**: 내장 GPU(Vulkan)에서의 속도. 이 PC는 내장 GPU가 꺼져 있다.
- 판단 모델이 바뀌면 문서의 "Laya" 표현을 "판단 모델"로 정리해야 한다.
