# 100문장 비교 분석 (2026-10-27, #25)

- 자동 생성 비교표: [README.md](README.md) · 행 단위 결과: `*.csv` · 실행 조건: `*.json`
- 조건
  - 실행 PC: Ryzen 7 7800X3D(8코어), RAM 32GB
  - 로컬 판단: Ollaya CPU 전용 (`OLLAYA_DEVICE=cpu`)
  - 클라우드 판단: OpenAI Decisions `gpt-6-luna`
- 기준값은 2겹 교차검증으로 정했다. 같은 문장으로 기준값을 정하고 평가하지 않는다.
- **테스트셋 라벨은 검토 전**이다(#6). 정답 '예'가 기밀 7, 위험 7, 원본 필요 10개뿐이라, 교차검증 기준값이 흔들린다.

## 결론: 판단을 "원본이 필요한가"로 나눈다

| 판단 | 원본을 봐야 하나 | 담당 | 결과 |
|---|---|---|---|
| 정규식이 놓친 이름·주소 | **예** (가리지 못한 원본이 남아 있는지 보는 판단) | **로컬** `gliclass:v4-edge` (noul) | 민감정보 재현율 **29/30**, 오탐 7/70 (AUC 0.96) |
| 기밀 | **예** (기밀은 가명화로 가려지지 않음, 엄격 수준에서는 밖으로 나가기 전에 차단) | **로컬** `gliclass:v4-edge` (noul) | AUC **0.99**. 교차검증 기준값은 재현율 4/7·오탐 3/93 (정답 '예'가 7개라 불안정) |
| 원본 값 필요 | 아니오 ("[주민번호1]로 나이 계산" 같은 가명화 문장으로 판단 가능) | **클라우드** Decisions + **코드 조건**(가명화된 개인정보가 있을 때만) | AUC **1.00**. 개인정보가 있는 '아니오' 문장은 전부 확률 0.0, 정답 '예'는 전부 0.02 이상 |
| 위험·인젝션 | 아니오 | **클라우드** Decisions (판단 거부도 '위험'으로 처리) | 재현율 **7/7**, 오탐 **0/93** (AUC 1.00) |
| 난이도 | 아니오 | **클라우드** Decisions | AUC 0.99, 보정 후 정확도 **0.86** (다수결 기준선 0.61) |
| 의도 | 아니오 | **클라우드** Decisions | 정확도 **0.89**. FAQ **15/15**, 무관 6/6 |

- **지연**
  - 로컬: `gliclass:v4-edge`는 질문당 0.18초라, 질문 2개면 약 0.35초다.
  - 클라우드: Decisions는 질문 5개에 평균 0.36초다(왕복).
- **메모리 (로컬, 실측)**: `gliclass:v4-edge`는 서버 프로세스를 포함해 2.2GB다. GPU는 쓰지 않는다.
- **비용 (클라우드)**: 판단 요청 1건에 입력 약 830토큰, 출력은 무료라 요청당 약 $0.00008이다.
- **라이선스**: 로컬 판단 모델은 Apache-2.0이다. 클라우드 판단은 정상적인 API 사용이고, 학습에 쓰지 않는다.

## 측정하며 발견한 것

1. **질문 문장 하나로 결과가 뒤집힌다.** 클라우드 원본 필요 질문이 두 문장이었을 때("…필요한가? 가려도 답할 수 있다면 필요하지 않은 것이다") 모델이 뒷문장에 답해 **AUC 0.25**가 나왔다. 한 문장으로 고치자 **0.98**이 됐다. predicate 질문은 한 문장으로 쓴다.
2. **판단 거부(refusal)는 위험 신호다.** Decisions는 10문장의 판단을 거부했다. 원본 필요 3개, 미공개 실적 1개, 위험·인젝션 7개 중 6개였다. 게이트웨이는 거부를 "차단" 쪽으로 처리한다.
3. **의도의 오답 대부분은 분류 정의의 빈칸이다.** "니트 세탁", "사이즈 추천", "운동화 관리" 같은 **상품 문의**를 FAQ / 업무 / 무관 셋 중 어디에도 넣기 어렵다. 그래서 모델이 '무관'으로 답했다(7건 중 5건). → 의도 선택지와 라벨을 함께 고친다 (#6).
4. **원본 필요는 코드 조건과 함께 써야 한다.** 개인정보가 없는 문장은 원본이 필요할 수 없다. "가명화된 개인정보가 있을 때만 묻기"를 코드로 걸면 로컬·클라우드 모두 오탐이 크게 준다(계산·조건은 코드에서: 설계 결정 6번).
5. 로컬 후보 중 `laya:multilingual`은 가장 빠르지만(질문당 0.06초) 보안 판단의 신호가 약했다. `d3:edge`는 위험 판단만 좋았다(AUC 0.95).

## 남은 확인

- 라벨 검토(#6) 후 같은 스크립트로 재측정한다. 질문별 기준값을 확정하고, 기밀·원본 필요는 정답 '예'가 적으니 기준값을 보수적으로(놓치지 않는 쪽으로) 정한다.
- 로컬 판단은 실제로는 가명화가 끝난 문장에서 "남은 개인정보"를 묻는다. 이번 측정은 원문의 민감정보 전체를 물은 근사다 → M2 가명화 구현 후 다시 잰다.
