# 생성 모델 시험 (#21, 2026-10-30)

파인튜닝용 한국어 요청 문장을 어느 로컬 모델로 만들지 고르는 시험이다.

**결론: `gemma4:12b`를 쓴다.** 조건을 가장 잘 지키고, 문장이 가장 자연스러우며 말투도 고르게 섞인다. GPU에 다 들어가 빠르다.

## 조건

| 항목 | 값 |
|---|---|
| 실행기 | `bench/generator_trial.py` (조건 8개 × 10문장 × 모델 3개 = 240문장) |
| 환경 | Ollama 0.40.13, RTX 4080 SUPER 16GB (드라이버 617.42), Ryzen 7 7800X3D, RAM 32GB |
| 샘플링 | temperature 0.8, seed 42, 모든 모델 같은 프롬프트 |
| 추론 | gemma4 `think=false`, gpt-oss `think=low`(끌 수 없음), mistral 추론 기능 없음 |
| 모델 | `gemma4:12b`(Q4_K_M), `gpt-oss:20b`(MXFP4), `mistral-small3.2:24b`(Q4_K_M) |

- `qwen3.8:27b`는 보안 보고로 시험에서 뺐다 (`docs/llm-api-notes.md` §5).
- 테스트셋 문장은 프롬프트에 넣지 않았다.

## 코드로 잰 것

| | gemma4:12b | gpt-oss:20b | mistral-small3.2:24b |
|---|---|---|---|
| 문장 수 (JSON 형식) | 80/80 | 80/80 | 80/80 |
| 한국어 (한자·가나 없음) | 80/80 | 80/80 | 80/80 |
| 개인정보 값 조건 (측정용 정규식) | 79/80 ※ | 79/80 | 80/80 |
| 같은 조건 안 중복 | 0 | 0 | 0 |
| 테스트셋과 유사도 0.8 이상 | 1 (최대 0.86) | 2 (최대 0.82) | 0 (최대 0.73) |
| 초당 출력 토큰 (중앙값) | 118 | 136 | 23 |
| GPU에 올라간 비율 | 100% | 100% | 90% |
| 8개 조건 전체 시간 | 21초 | 18초 | 85초 |

※ gemma4의 1건은 측정용 주소 정규식의 오탐이다. "내년**도** 연**구**개발비**로** 30억"이 `시·도 + 구·군 + 로·길 + 숫자` 모양에 걸렸다. M2에서 실제 마스킹을 만들 때 주소 패턴을 더 좁혀야 한다.

- **자동 검사로는 세 모델 차이가 거의 없다.** 품질 차이는 직접 읽어야 보인다.
- 테스트셋과 비슷하게 나온 문장은 "반품하고 싶은데 어떻게 해야 돼?"처럼 짧은 단순 문의뿐이다. 실제 생성 단계의 품질 기준에서 걸러낸다.

## 직접 읽은 것 (`side-by-side.md`, Claude가 읽고 분류)

| | gemma4:12b | gpt-oss:20b | mistral-small3.2:24b |
|---|---|---|---|
| 라벨이 틀어지는 문장 | **2** | 4 | 5 |
| 형식·문법·부자연 | **0~1** | 14 | 약 9 |
| 존댓말·반말 섞기 | **고르게 섞음** | 대부분 존댓말 | 섞음 |
| 지어낸 번호의 다양성 | **무작위처럼 보임** | 반복 숫자(`010-5566-7788`) | 연속 숫자(`010-1234-5678`, `2345-6789` …) |

**gemma4:12b**
- 기밀 조건 10개 중 2개(#3, #7)가 기밀 내용 없이 "알려줘"라고만 묻는다. 나머지는 "목표 금액 1,500억 원", "개당 4,500원·10만 개"처럼 구체적인 내용이 문장에 들어 있다.
- 복잡한 업무 요청이 가장 길고 구체적이다(여러 조건을 묶은 지시).
- 주민번호 뒷자리 첫 숫자와 생년도가 맞는다. 예: `010215-4…`는 2000년대생 여성이다.

**gpt-oss:20b**
- **기밀 조건 10개가 모두 요청이 아니라 사실 진술이다**("인수금액은 3억 5천만 원이며 …"). 템플릿도 A사~K사로 반복된다.
- 병원 문자 조건에서 "메일 주소는 010-1234-5678"처럼 논리가 틀린 문장이 2개 나왔다.
- 위험 조건 2개("기록하지 않도록 해줘", "민감한 문장을 삭제해줘")는 위험하지 않다. 무관 조건 1개("가장 인기 있는 상품은 뭐야")는 쇼핑몰 업무 질문이다.
- 첫 프롬프트에서는 "[환자1]처럼 가명으로 바꿔도 되는 요청"이라는 설명을 보고 실제 이름 대신 `환자1`을 썼다. 예시를 글자 그대로 따라 하는 경향이 있다. 이 시험은 설명을 고친 두 번째 프롬프트로 돌렸다.

**mistral-small3.2:24b**
- 개인정보 단어만 있어야 하는 조건 4개에 실제 이름("김철수 씨", "이정민입니다")이 들어갔다. 라벨이 has_pii=1로 바뀌는 오류다.
- 문법 오류가 있다: "들렸는데"(→ 들었는데) 4번, "몇일"(→ 며칠), "분석해줜다".
- 기밀 조건은 "~라는 게 사실인가요?"처럼 소문을 확인하는 질문 위주다.
- 한국어를 공식 지원 언어로 적은 모델이지만, 이번 시험에서는 가장 부자연스러웠다. 권장 temperature가 0.15인데 0.8로 돌린 영향일 수 있다.

## 시험 중 생긴 일

- gpt-oss를 다른 모델 다음에 올릴 때 Ollama 실행기가 CUDA 초기화에서 죽었다(`0xc0000409`, `shared object initialization failed`). 실행 인자는 성공할 때와 같았다.
- Ollama 서버를 다시 시작하자 해결됐다. 그래서 실행기에 두 단계를 넣었다.
  - 측정 전 워밍업: 최대 5번 시도하고, 시도 횟수를 기록한다. gpt-oss는 2번째에 올라갔다.
  - 실행기 오류일 때 한 번 다시 시도한다.
- 모델 출력 자체는 다시 시도하지 않았다.

## 한계

- 조건마다 10문장, seed 하나다. 모델 사이의 큰 차이는 보이지만, 작은 차이는 우연일 수 있다.
- 직접 읽은 평가는 Claude가 했다. 문장이 자연스러운지는 사람이 다시 확인해야 한다.
- 실제 생성 단계에서는 전화번호·주민번호 같은 값을 **코드가 무작위로 만들어 끼워 넣는다**. 그러면 위의 "번호 다양성" 차이는 사라진다.
