## 4. 기능마다 생성형 AI가 하는 일

| 기능 | AI가 하는 일 | 코드가 하는 일 |
|---|---|---|
| 가명화 | 이름 인식 모델이 사전에 없는 이름의 **위치**를 찾는다 | 정규식·사전으로 찾고, 토큰으로 바꾸고, 답변에서 되돌린다 |
| 기밀 판단 (로컬) | 판단 모델이 원문을 보고 "기밀인가"의 확률을 낸다 | 기준값과 비교해 엄격 수준에서 막는다 |
| 라우팅 (클라우드) | Decisions가 가명화된 문장으로 원본 필요·위험·난이도·의도를 판단한다 | 판단 결과로 템플릿·저렴·고성능·차단을 고른다 |
| 답변 | LLM이 **가명 토큰이 든 요청으로** 답을 쓴다 | 토큰을 원래 이름·번호로 되돌린다 |
| FAQ | (쓰지 않음) | 등록된 질문은 템플릿으로 답한다. 밖으로 아무것도 나가지 않는다 |

## 5. 직접 말해야 할 한계 (Q&A)

| 질문 | 답 |
|---|---|
| 이름을 다 가리나요? | 99%를 가린다. 붙여 쓴 이름("환자분양소윤님께")이나 일반 낱말과 같은 이름("정하늘")은 놓칠 수 있다. 고객명을 사전에 등록하면 100%다 |
| 엉뚱한 것을 가리지는 않나요? | "금식", "노쇼" 같은 업무 낱말을 이름으로 가리는 경우가 있다(정밀도 96~97%). 답변에서는 되돌아온다. 막히는 경우는 M4에서 낱말 목록으로 줄인다(#65) |
| 문서도 되나요? | 번호·이메일·주소·이름은 길이와 관계없이 끝까지 가린다. 기밀 판단 모델은 한 번에 약 1,200자를 읽어서 긴 글은 나눠 판단한다(#39, #71). 파일은 파일 검사 기능으로 가명화된 텍스트를 만든다 |
| 엄격 수준은 정상 요청도 막나요? | 기밀 판단 오탐이 한 줄 요청 기준 12%다. 엄격 수준은 일부러 막는 쪽으로 틀리게 했다. 기본 수준은 기밀로 막지 않는다 |
| 왜 판단을 클라우드에도 보내나요? | 원본을 봐야 하는 판단(기밀)만 로컬에서 한다. 클라우드에는 가명화된 문장만 간다(D12). 전부 로컬로 하는 파인튜닝 모델도 만들어 봤는데, 기밀·위험 판단이 목표에 못 미쳤다(#22) |
| 비용이 정말 줄어드나요? | 단순 요청은 95~100% 준다. 전체 절감률은 요청 구성에 달렸다. 복잡한 요청이 많은 이 테스트셋에서는 10%였다 |
