# 가명화 (`gateway/masking/`, #44)

밖(클라우드 판단·LLM)으로 나가기 전에 개인정보를 `[고객1]`·`[전화번호1]` 같은 토큰으로 바꾼다. LLM 답변의 토큰은 원래 값으로 되돌린다. 복원 대응표는 요청 처리 중 메모리에만 있다.

**생성형 AI의 역할**
- 가명화는 **코드**가 한다(설계 결정 1번).
- AI는 가린 뒤 "남은 개인정보가 있는가"를 판단하는 자리(로컬 판단)에만 있다.
- LLM으로 가리는 방식은 쓰지 않는다. 복원이 깨질 수 있고, 프롬프트 인젝션에 약하다(11/01 논의, #42).

## 파일
| 파일 | 역할 |
|---|---|
| `patterns.py` | 형식 있는 값의 정규식: 주민번호·카드번호·전화번호·이메일·계좌번호·주소 (#11에서 보안 검토 3번) |
| `dictionary.py` | 사용자 사전: 회사가 등록한 고객명·직원명·사내 고유명사 |
| `masker.py` | 가명화 부품. `RuleMasker`(기본: 사전 + 정규식), `UnavailableMasker`(가명화 없음 → 개인정보 요청 차단) |

## 규칙 (`RuleMasker`)
- 순서: **사전**(긴 값부터: "김민수"보다 "김민수진" 먼저) → **정규식**
- **같은 값 = 같은 토큰**. 한 요청 안이면 메시지가 달라도 같다.
- **메시지 전체**를 가린다: system·user·assistant·tool (#37).
  - 복원된 답변이 다음 요청의 대화 이력으로 돌아온다.
  - 도구 결과에는 회사 DB의 고객 정보가 들어 있다.
- 입력에 이미 `[고객1]` 같은 글자가 있으면 그 번호는 건너뛴다. 복원할 때 사용자가 쓴 글자를 다른 값으로 바꾸지 않기 위해서다.
- 날짜(`2026-11-03`), 주문번호·운송장 번호는 가리지 않는다.

## 표기 정규화와 마지막 검사 (11/02 보안 검토)
같은 값을 다른 표기로 써서 사전·정규식을 피하는 것을 막는다. 보안 검토가 네 번 지적했고, 모두 직접 재현한 뒤 고쳤다.

| 우회 표기 | 처리 |
|---|---|
| 자모를 나눠 쓴 "김민수"(NFD) | NFC로 합친다 |
| 폭 0 공백·소프트 하이픈·BOM·방향 표시(`김​민수`) | 보이지 않는 서식 문자(Cf)를 지운다 |
| 한글 채움 문자 `ㅤ`(U+3164, 빈 닉네임에 흔함)·결합 문자 연결자·이체 선택자·점자 빈칸 | 유니코드 기본 무시 문자 전체를 지운다 |
| 아랍-인도·데바나가리 등 다른 문자권 숫자 | 0~9로 |
| 엔대시·엠대시·유니코드 하이픈·빼기 기호(`010–1234–5678`) | 하이픈으로 |
| 전각 숫자·공백(`０１０　１２３４`) | 반각으로 |
| 영문 대소문자(`x-프로젝트`) | 사전 비교에서 무시, 같은 토큰 |
| **동그라미 숫자, 수학 글꼴 영문 등**(`⓪①⓪-…`, `𝐗-프로젝트`) | 정규화로 못 가린다 → 가린 뒤 문장의 **검사용 사본**(결합 표시 제거 + NFKC)에서 형식 있는 개인정보나 **사전 값**이 보이면 **차단**(`pii_unmasked`, 보안 수준 무관). 로그에도 남기지 않는다 |

- NFKC로 문장 자체를 바꾸지 않는 이유: "ㅋㅋ"·"ㅠㅠ" 같은 한글 낱자를 조합용 자모로 바꿔 버린다(확인함). 그래서 NFKC는 검사용 사본에만 쓴다.
- 밖으로 나가는 문장은 정규화된 표기다(보이지 않는 문자가 빠지고 대시가 하이픈으로 바뀌는 정도).

## 사용자 사전
```
# private/user_dictionary.txt (커밋하지 않는다)
고객,김민수
직원,최유진
사내,X-프로젝트
박지훈            ← 종류가 없으면 고객
```
- 종류가 토큰 이름이 된다(`[고객1]`, `[직원1]`, `[사내1]`). LLM도 `[직원1]`이 직원이라는 걸 알아야 문장을 자연스럽게 쓴다.
- **실제 사전이 없으면 시연용 가상 사전**(`config/user_dictionary.example.txt`, 커밋됨)을 쓰고 로그에 경고를 남긴다. 새 PC에서도 설치하자마자 시연 4번이 된다(11/02 결정).
- 오류 메시지에는 줄 번호만 넣는다. 값(실제 이름)은 남기지 않는다. 한 글자 값은 다른 낱말까지 가려서 받지 않는다.

## 알려진 한계
- **사전에 없는 이름**은 가려지지 않는다. 정규식은 이름을 못 잡는다 → #42(NER 모델 후보), #46(재현율 측정)
- 이름이 다른 낱말 안에 있어도 가린다(예: 사전의 "이슬"이 "이슬비" 안에서도 가려짐). 한국어는 조사가 붙어 낱말 경계를 정하기 어렵다. 오탐은 복원 단계에서 되돌아온다.
- 조사 교정(`[고객1]은` → 김민지는)과 LLM이 바꿔 쓴 토큰 처리는 #45에서 한다.

## 실제 호출 확인 (11/02, Ollaya + OpenAI, 기본 수준, 시연용 사전)

| 요청 | 밖으로 나간 문장 | 경로 | 받은 답변 |
|---|---|---|---|
| 시연 3번 | (나가지 않음) | 템플릿 | 배송 안내 |
| 시연 4번 | `[고객1] 고객([전화번호1])에게 배송 지연 사과 메일 써줘` | 저렴 | "안녕하세요, **김민수님**. …" (복원됨) |
| 시연 5번 `900101-1234567 이 주민번호로…` | `[주민번호1] 이 주민번호로 고객 나이 계산해줘` | 차단 (원본 필요) | 안내문 |
| 사전에 없는 이름 | `홍길동 고객님께 주문 확인 문자…` (**원본 그대로**) | 저렴 | — |

### 발견: 로컬 판단 모델은 가명화된 문장에서 "남은 개인정보"를 거꾸로 답한다
| 문장 | 실제 | `gliclass:v4-edge` P(남은 개인정보) | 기준값 0.09 기준 |
|---|---|---|---|
| `[고객1] 고객([전화번호1])…` (전부 가려짐) | 없음 | **0.54** | "있음" ❌ |
| `홍길동 고객님께…` (사전에 없는 이름) | 있음 | **0.08** | "없음" ❌ |

- 기준값 0.09는 **원문**으로 잡았다(M0). 가명화된 문장으로는 잰 적이 없다.
- 모델이 `[고객1]` 같은 토큰을 개인정보로 본다.
- 영향
  - **기본 수준**: "남은 개인정보"로 막지 않으므로 지금 동작은 그대로다. 대신 사전에 없는 이름은 나간다.
  - **엄격 수준**: 이 판단으로 막기 때문에 **시연 4번처럼 다 가려진 요청까지 막힌다**(`pii_residual`).
