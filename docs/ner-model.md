## 측정 (11/07, `bench/results/names-2026-11-07/summary.md`)

사전은 시연 사전만 쓴다(사전에 없는 이름이 남는다). 목표는 이름 재현율 ≥ 95%, 잘못 가린 문장 ≤ 5%다.

| 방법 | 테스트셋 재현율 / 잘못 가림 | 파일럿(테스트셋 밖) | 드문 이름 | 지연 |
|---|---|---|---|---|
| 판단 모델로 후보 판단 (가장 나은 조합) | 97% / 42% | 96% / 32% | 93% / 85% | 459ms |
| **이름 인식 모델 int8** | **97% / 2%** | **100% / 1%** | **98% / 0%** | **2ms** |
| 이름 인식 모델 fp32 | 97% / 2% | 100% / 1% | 98% / 0% | 2ms |

- 판단 모델은 "고객"·"민원인"·"우리"도 이름으로 봤다. 이름 인식 모델은 이런 낱말을 건드리지 않았다.
- 이름 인식 모델은 기준값 없이 모델이 붙인 라벨을 그대로 쓴다(테스트셋에 맞춘 값이 아니다).
- 놓친 이름 2개: "정하늘 고객에게"(이름 끝이 일반 낱말 "하늘"과 같다), "온결"(아주 드문 성 + 외자 이름).
- 잘못 가린 낱말: "금식", "휴진", "내원", "상방/하방", "쇼", "김OO"(이름 자리표시) 등. 한 글자("쇼", "O")는 사전과 같은 "두 글자 이상" 규칙으로 걸러진다.
- 성씨 목록에 없는 성("묵하진", "섭지우")도 찾았다. 모델은 성씨 목록을 쓰지 않는다.

## 게이트웨이에서 쓰는 방법 (11/07, D23)

| 항목 | 값 |
|---|---|
| 설정 | `config.yaml`의 `masking.ner` (`model_dir`, `onnx_file`). 기본은 int8 |
| 자리 | 가명화 순서 사전 → **이름 인식** → 회사별 식별번호 → 정규식 → 마지막 검사 (`gateway/masking/masker.py`) |
| 이름 | 사전에 없는 이름을 `[이름1]`로 가린다. 두 글자 이상, 숫자 없는 것만. 사전에 있는 이름은 사전 종류(`[고객1]`) |
| 주소 | 가리지 않는다. 가린 뒤에도 모델이 본 주소가 그대로 있으면 `suspected` → 엄격 수준은 차단(`pii_residual`), 로그에는 문장을 남기지 않는다 |
| 긴 글 | 256토큰 구간(겹침 64)을 8개씩 묶어 계산한다. 512토큰 한 구간보다 빠르고(7.6만 자 4.1초 → 2.5초), 세 세트 477문장의 결과는 글자 위치까지 같았다 |
| 시작할 때 | 파일 3개(`config.json`, `tokenizer.json`, ONNX)를 한 번 읽어 해시를 확인하고 그 바이트로 불러온다. `/healthz`의 `ner`에 파일 이름이 보인다 |
| 네트워크 | 쓰지 않는다. 연결을 막은 상태에서 불러오기·찾기가 되는지 시험한다(`tests/test_ner.py`) |

실제 연결(설정 → `RuleMasker.from_config` → 이 모델, 시연 사전만)로 세 세트를 다시 잰 값:

| 세트 | 이름 가림 | 잘못 가린 문장 | 엄격 수준에서 "남은 주소"로 막힘 | 지연 평균 (가명화 전체) |
|---|---|---|---|---|
| 테스트셋 | 43/44 (사전 이름 포함) | 4/190 | 0/190 | 1.9ms |
| 파일럿 | 24/24 | 2/246 | 0/246 | 1.9ms |
| 드문 이름 | 43/44 | 0/41 | 0/41 | 2.4ms |

정규식이 못 잡는 주소의 예 ("마포구 가상로 123", "가상아파트 101동 1001호")는 모델이 주소로 찾았다. "요구 사항으로 3개", "본사 회의실 3층"은 주소로 보지 않았다.
