## 1. OpenAI ([문서](https://developers.openai.com/api/docs))

**(10/30 다시 확인)** [가격](https://developers.openai.com/api/docs/pricing) · [모델](https://developers.openai.com/api/docs/models) · [지원 종료](https://developers.openai.com/api/docs/deprecations) 페이지 기준, Standard 요금, 입력 272K 토큰 이하

| 용도 | 모델 | 가격 (100만 토큰당 입력 / 캐시 입력 / 출력) | 비고 |
|---|---|---|---|
| **저렴한 모델 (채택, D17)** | `gpt-6-luna` | $0.10 / $0.01 / $0.50 | "가장 효율적인 모델". 추론 강도 none~max (기본 medium) |

| 중간 | `gpt-6.1-terra` | $1.00 / $0.05 / $5.00 | 빠르고 효율적, 자연스러운 글쓰기 |

| 최상위 | `gpt-6-astra` | $10.00 / $1.00 / $50.00 | 비교 기준으로 쓰면 절감액이 부풀려 보임 |
| 지원 종료 예정 | `gpt-5-nano`, `gpt-5-mini` | $0.05 / $0.40, $0.25 / $2.00 | **2026-12-11 종료** (최종 평가 12/8 직후) → 쓰지 않음 |

- 학교 키로 `GET /v1/models`를 조회해 위 모델에 모두 접근할 수 있음을 확인했다 (10/30).
- GPT-6 계열은 추론 모델이다. 추론 토큰은 `completion_tokens`에 들어가 출력 가격으로 청구된다.
- Chat Completions에서 함수 호출은 `reasoning_effort: none`일 때만 된다(모델 페이지). 게이트웨이는 함수 호출을 쓰지 않는다.
- 캐시 쓰기는 입력 가격의 1.25배다. 우리 요청은 1,024토큰보다 짧아 캐시 대상이 아니라서 비용 계산에서 뺀다.
- Batch(비동기 대량 처리)·Flex는 표준 가격의 절반이다.
- JSON 스키마를 따르는 출력(Structured Outputs)을 지원한다.
- **Decisions API** (`POST /v1/decisions`, `gpt-6-luna`)
  - 클라우드 판단 모델이다. 질문 타입은 `predicate` / `choice` / `score`이고, 입력 $0.10, 출력은 무료다.
  - 요청 필드가 `model`·`input`·`questions`라서 `/v1/systemone`(`state`)과 형식이 같다는 언급은 없다.
  - 원문을 클라우드로 보내므로 "판단도 로컬" 원칙에 맞지 않는다. 비교 실험용(선택)으로만 고려한다.

## 3. 출력으로 모델을 학습시켜도 되는가 (공개 약관 기준)

| 데이터를 만든 곳 | 조항 요지 | 우리 계획(파인튜닝 모델을 공개 저장소·설치 스크립트로 배포)에 미치는 영향 |
|---|---|---|
| xAI (기업용 약관) | 주문서에 따로 허용되지 않으면 출력으로 **어떤 AI 시스템도 학습 금지** | 사용 불가 |
| OpenAI (서비스 계약 §3.3(e), 정의) | 출력으로 **OpenAI와 경쟁하는 AI 모델 개발 금지**. 예외: 분류·범주화가 주목적인 모델이면서 **제3자 배포·상업 제공을 하지 않는 경우** | 시연 PC에서만 쓰면 예외에 해당. 배포하면 예외를 벗어남. OpenAI가 판단 모델(Decisions)을 팔고 있어 경쟁으로 볼 여지가 큼 |
| Anthropic 소비자 약관 (개인 구독, 2025-10-08) | 모델 개발·학습을 포함해 **경쟁하는 상품·서비스 개발 금지** | "경쟁" 여부는 해석의 문제라 확실하지 않음 |
| Anthropic 상업용 약관 (API, 2025-06-17) §D.4 | 경쟁 상품을 만들거나 **경쟁 AI 모델 학습** 금지. 경쟁하지 않는 학습에 대한 명시적 금지는 없음 | 해석의 여지가 있음 |
| 로컬 오픈 모델 (Apache-2.0 등) | 라이선스상 출력 사용 제한 없음. 단 모델마다 다르다 → §5 (10/30 모델별 확인) | Apache-2.0·MIT는 문제없음. 국내 모델 일부는 조건 있음 |

- 네 약관 모두 출력물의 **소유권은 사용자**에게 준다. 하지만 학습 사용은 이용 계약상 행위 제한으로 따로 막는다. 소유권이 있다고 학습에 써도 되는 것은 아니다.
- 학교 지원 키에는 학교 계약이 따로 적용될 수 있다 → (10/27 면담 답변) 학교 키는 일반용이라 공개 약관이 그대로 적용된다 (`docs/meetings/2026-10-27.md`).
- 테스트셋(`data/testset.csv`)은 평가에만 쓰고 학습에는 절대 넣지 않는다.

## 4. #21 학습 데이터 품질 기준

우리 판단 질문은 고정된 몇 개짜리 분류라, 학습 데이터의 질은 **문장이 얼마나 유려한가보다 라벨이 맞는가와 경계 사례가 있는가**로 정해진다.

| 기준 | 목표 | 확인 방법 |
|---|---|---|
| 라벨 정확도 | 검토 표본의 오류율 **5% 이하** | 무작위 50개 직접 검토 |
| 경계 사례 | 판단마다 헷갈리는 쌍 포함 (예: 주문번호 vs 계좌번호, 가려도 답할 수 있음 vs 실제 값 필요, 짧지만 복잡한 요청) | 범주별 개수 집계 |
| 다양성 | 말투(존댓말·반말·오타), 길이, 채널(채팅·메일), 업무(고객센터·사내) 조합 | 생성 조건을 무작위로 섞음, 중복 제거 |
| 분리 | 테스트셋과 문장·이름이 겹치지 않음 | 자동 겹침 검사 |
| 균형 | 판단마다 '예'가 너무 적지 않게 | 범주별 개수 집계 |

- 생성 모델이 작을수록 문장이 단조롭고 지시를 어길(라벨과 안 맞는 문장을 만들) 가능성이 커진다. 그래서 생성 후 **자동 검증 → 표본 검토 → 오류율 게이트**를 거친다.
- 최종 판정은 데이터 자체가 아니라 **파인튜닝한 모델의 테스트셋 점수**로 한다 (목표선: `d1:3b` 100문장 점수).

## 5. #21 생성용 로컬 모델 라이선스 (2026-10-30 확인)

- 조건: 이 PC(RTX 4080 SUPER 16GB)에서 돌릴 수 있고, 출력으로 학습한 Laya를 **공개 배포**해도 제약이 따라오지 않아야 한다.

- 후보 3개(Gemma 4, gpt-oss, Mistral Small 3.2)는 **우리 한국어 문장으로 직접 생성 품질을 시험**한 뒤 고른다. 한국어를 명시한 것은 Mistral뿐이다.
- **시험 결과 (10/30): `gemma4:12b`로 정했다.** 자동 검사(형식·한국어·개인정보 값·중복)는 세 모델이 비슷했다. 직접 읽어 보면 차이가 났다.
  - gemma4: 조건을 가장 잘 지키고 말투가 고르게 섞인다. 초당 118토큰, GPU 100%.
  - gpt-oss: 기밀 요청을 사실 진술로 썼고, 예시를 글자 그대로 따라 했다.
  - Mistral: 문법 오류가 있었고, 초당 23토큰으로 느렸다.
  - 근거: `bench/results/generator-trial-2026-10-30/summary.md`
- **Qwen3.8 제외 이유 (10/30)**: Cohere가 10/26에 보고했다. 도구(셸)를 가진 에이전트 시험에서 `Qwen3.8-Flash-Next`가 지시에 없던 `curl` 업로드를 Alibaba Cloud 저장소(베이징)로 시도했고, 샌드박스가 막았다. 빈도는 10만 번에 1번 미만이다.
  - 원인은 아직 모른다. 학습 데이터 잔재라는 설명과 의도적 백도어라는 가설이 둘 다 있고, Alibaba는 공식 답변을 내지 않았다.
  - 우리가 쓰는 27B dense 모델은 시험 대상이 아니었다. 도구 없이 Ollama로 글만 생성하면 모델이 스스로 네트워크에 접근할 수 없다.
  - 그래도 제외하는 이유: 출력이 배포할 모델의 **학습 데이터**가 되므로 숨은 동작이 섞일 가능성을 0으로 만들 수 없다. **보안 제품**의 데이터 출처로 설명하기도 어렵다. 같은 Apache 2.0 대안(Gemma 4, gpt-oss)이 있고, 16GB GPU에 다 들어가지도 않는다.
  - 출처: [Cohere 블로그](https://cohere.com/blog/concerning-behaviour-popular-open-weight-ai-model), [The Register](https://www.theregister.com/ai-and-ml/2026/10/26/alibabas-qwen-ai-caught-trying-to-contact-server-in-china/5305561)
- 공식 Ollama 라이브러리에 있는 모델을 우선한다. 출처를 확인하기 어려운 커뮤니티 GGUF는 받지 않는다.
