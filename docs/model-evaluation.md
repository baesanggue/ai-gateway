# 판단 모델 테스트 기록

어떤 판단 모델을 어떤 방법으로 시험했고, 무엇이 맞고 안 맞았는지 모은 문서다. (10/27 면담 의견 4번)
상세 수치와 원자료는 각 결과 폴더에 있다.

## 시험 방법 (공통)

- 데이터: `data/testset.csv` (한국어, 쇼핑몰 고객센터·사내 업무 100문장, 이름·번호는 전부 가상 값)
- 판단 질문: 민감정보, 원본 값 필요, 기밀, 위험·인젝션, 난이도, 의도 (`bench/spike_laya.py`의 질문 문장)
- 지표: 정확도뿐 아니라 **다수결 기준선**, **'예' 재현율·오탐**, **AUC**(기준값과 무관한 구분 능력)를 함께 본다. 정답 '예'가 적은 판단은 정확도만 보면 속는다.
- 기준값: 100문장 비교부터는 2겹 교차검증(홀수/짝수 행)으로 정한다.
- 로컬 모델은 Ollaya 0.18.0에서 CPU 전용으로 잰다 (`OLLAYA_DEVICE=cpu`, 결과에 VRAM 0 기록).
- 실행 PC: AMD Ryzen 7 7800X3D(8코어), RAM 32GB, RTX 4080 SUPER(GPU 측정 때만 사용), Windows 11

## 결정으로 이어진 것

- D10: 판단 정확도 대응을 10/28로 앞당김 (#5 결과)
- D11: 판단 모델은 같은 시험지로 재서 고름 (#18 결과)
- D12: **원본을 봐야 하는 판단은 로컬, 가명화 문장으로 충분한 판단은 클라우드** (#25 결과)
- D13: 범용 구조 + 업종별 검증. 190문장에서 채택 구성이 업종을 바꿔도 유지됨을 확인 (#27 결과: 민감정보 56/57, 위험 13/13·오탐 0, 원본 필요 16/18·오탐 1, 난이도 0.94, 의도 0.96(거부 제외))
- D14 M2 재측정 (#46, 11/06): 클라우드 판단은 경보선을 모두 넘음(원본 필요 18/18·오탐 1, 위험 13/13·오탐 0, 난이도 0.96, 의도 0.96). 로컬 기밀은 기준값 0.12에서 11/13으로 경보선 아래. 로컬 남은 개인정보 판단은 차단 근거로 쓰기 어렵다
- 알려진 한계였던 것: Decisions의 판단 거부가 정상 요청 4건(4/147 = 2.7%, 처음에 2.4%로 잘못 계산)을 막음 → 다시 물어도 똑같이 거부했다. 난이도·의도 질문의 거부는 고성능으로 보내기로 해서 0%로 해결 (D16, #8)
- D23 (#53, 11/07): 판단 모델로 이름 후보를 판단하는 방법은 실패(잘못 가린 문장 32~85%). 이름 인식 모델이 세 세트 모두 목표를 넘어 가명화 단계에 넣고, 엄격 수준의 "남은 개인정보" 판단을 그 모델의 "남은 주소" 확인으로 바꿈
- D15 #22 (11/07): 파인튜닝한 Laya 하나로 판단 5개를 전부 로컬에서 하면 원본 필요·난이도·의도는 목표를 넘지만 기밀(62%)·위험(85%)이 못 미침 → 하이브리드 유지. 같은 생성기로 만든 평가 데이터의 99%는 실제 성능을 말해 주지 않았다
