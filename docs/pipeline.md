# 요청 처리 흐름 (`gateway/pipeline.py`, #12)

요청 1건이 가명화 → FAQ → 로컬 판단 → 클라우드 판단 → LLM → 복원 → 로그를 지나는 길이다. 단계별 규칙은 각 모듈에 있고, 이 파일은 순서와 기록만 맡는다.

**생성형 AI의 역할**
- 판단 모델(로컬 소형 모델, 클라우드 Decisions)이 요청을 분류한다.
- LLM(저렴한·고성능 모델)이 가명화된 요청으로 답변을 쓴다.
- 흐름 자체는 코드다. 같은 판단이면 언제나 같은 길로 가야 하기 때문이다.

## 흐름

```
요청 ─▶ ① 가명화 ─▶ ② FAQ(코드) ──맞음──▶ 템플릿 답변 (외부 호출 0)
                       │
                       ▼
                ③ 로컬 판단 (밖으로 나갈 메시지 전체: 남은 개인정보·기밀)
                   ├ 가명화 부품 없음(M1): 개인정보가 보이거나 확인 못 함 → 차단 (masking_unavailable)
                   └ 엄격 수준: 기밀·남은 개인정보·로컬 실패 → 차단
                       │
                       ▼
                ④ 클라우드 판단 (가명화된 마지막 사용자 메시지: 원본 필요·위험·난이도·의도)
                   + 이전 대화·도구 결과·system 지시문의 위험 판단 (있을 때만, 확실한 판정은 10분 기억)
                       │ 차단 / 저렴 / 고성능
                       ▼
                ⑤ LLM (가명화된 대화 전체, 개인정보가 가려졌으면 "토큰을 그대로 써라" 지시)
                       │
                       ▼
                ⑥ 복원 → OpenAI 형식 응답        모든 경로: 요청 로그 저장 (#11)
```

## 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 판단 대상 | FAQ·클라우드 판단은 마지막 사용자 메시지, 로컬 판단은 메시지 전체 | LLM에는 대화 전체가 가므로 개인정보·기밀은 전부 봐야 한다 |
| **M1 가명화** | 부품 자리만 두고 "가명화 없음" 부품을 쓴다. 개인정보가 보이거나 확인 못 하면 **클라우드·LLM 전에 차단** | 흐름만 연결하면 원본이 OpenAI로 나간다(설계 결정 2번). M2에서 진짜 가명화 부품으로 바꾸면 이 차단은 사라진다 |
| 차단 응답 | HTTP 200 + 안내문 + `finish_reason: "content_filter"` | 기존 챗봇은 그대로 보여 주고, 프로그램은 차단을 알 수 있다 |
| 판단 과정 | 응답 본문에 넣지 않는다. 헤더 `x-gateway-request-id`로 로그를 찾는다 | 본문을 바꾸면 "base URL만 바꾸면 동작"이 깨질 수 있다. 데모 화면은 로그를 읽는다 |
| LLM 오류 | OpenAI 형식 502 (`upstream_error`), 로그에 오류 code | 상위 오류 내용은 응답에 넣지 않는다 |
| 인증 (D20) | `GATEWAY_API_KEYS`가 있으면 Bearer 필수. 없으면 같은 PC의 프로그램만(Host·Origin 확인) | 회사 OpenAI 키를 아무나 대신 쓰지 못하게 |

## 보안 검토로 보강한 것 (11/01)
커밋할 때마다 자동 보안 검토가 돌았고, 매번 직접 확인한 뒤 고쳤다.

| 지적 | 조치 |
|---|---|
| 판단한 글(마지막 메시지) ≠ 보낸 글(대화 전체) → 앞쪽 대화·도구 결과에 인젝션을 숨기면 우회 | 이전 대화·도구 결과도 위험 판단을 거친다 |
| system 메시지를 믿고 뺐다 → 클라이언트가 보내는 값이다 | system·developer도 넣는다. 같은 지시문은 결과를 기억한다. 끌 수 있다(`check_system_messages`) |
| 이전 대화 판단이 실패하면 그냥 통과 | 클라우드 판단 실패와 같이 `on_error_route`를 따른다 |
| 판단 캐시 오염: 여러 번 보내다 한 번 나온 "안전"이 고정됨 | 확실한 판정만, 10분, 설정별 키, 로그에 `cached` |
| 인증 없음 → 열린 프록시 | 게이트웨이 키 (D20) |
| 키 없는 모드에서 악성 웹페이지가 브라우저로 127.0.0.1 호출 | Host·Origin 확인, text/plain 거부 (D20) |

## 남은 결정
- **판단 실패 시 통과(D12)**: 클라우드 판단이 실패하면 `on_error_route: cheap`으로 LLM에 보낸다. 가용성을 위한 결정이지만, 공격자가 입력을 아주 길게 만들어 판단을 실패시키면 위험 판단을 건너뛴다. 엄격 수준에서 실패를 차단으로 바꿀지, 판단에 보내는 길이에 상한을 둘지 정해야 한다.
- 시연 5번 문장은 실제 번호가 있어야 "원본 필요"를 묻는다. 예: `900101-1234567 이 주민번호로 고객 나이 계산해줘` (CLAUDE.md 시연 문구는 M4에서 고친다).
