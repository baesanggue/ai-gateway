# 웹 체험판 운영 (#90, D28)

설문(사용자 10명 이상)을 위해 테스터에게 이 PC의 화면을 인터넷 주소로 연다. **완성품은 설치형**이고 체험판은 설문용이다.

## 무엇이 다른가 (`.env`에 `BETA_PASSWORD`가 있으면 켜진다)

| | 설치형 (평소) | 체험판 |
|---|---|---|
| 들어오기 | 이 PC에서만 | 인터넷 주소 + 공용 비밀번호. 틀림은 서버가 센다: 접속 주소 하나가 10분에 5번 틀리면 그 주소를, 모두 합쳐 50번 틀리면 모두를 10분 막는다 |
| 현황·요청 기록 | 모든 요청 | **이 세션이 보낸 요청만** |
| 설정 | 바꾸고 바로 적용 | **보기만** (사용자 사전·등록 지시문 탭 없음) |
| 시연 | 그대로 | 처음에는 처리 과정 칸에 체험판 고지 + 해 볼 것 4가지, 보낸 뒤에는 작은 창 |
| 사용량 | 제한 없음 | 한 사람 30회, 하루 전체 500회 (`config.yaml` beta) |
| 인터넷에 열리는 것 | 없음 | **화면(8501)만**. 게이트웨이(8000)·Ollaya(11435)는 그대로 127.0.0.1 |

- 테스터가 넣은 원문은 이 PC의 메모리만 거친다. 요청 기록에는 가명화된 문장만 남는다(설계 결정 2번). 외부 AI로는 가린 문장만 간다.
- 세션 상한은 새로고침하면 다시 시작된다. 비용을 확실히 묶는 것은 하루 전체 상한이다(하루 최대 약 $0.5).

## 여는 순서

1. `.env`에 `BETA_PASSWORD=`(설문 메시지로만 알린다)를 넣는다. 운영자가 직접 넣는다. **12자 이상**으로, 낱말 몇 개와 숫자를 섞어 맞히기 어렵게 한다(예: 낱말 3개 + 숫자 4자리). 인터넷에 열리므로 짧은 비밀번호는 쓰지 않는다
2. 개발 중 쌓인 요청 기록과 섞이지 않게 `data/gateway.db`를 다른 이름으로 옮겨 둔다(예: `data/gateway-dev-2026-11-11.db`). 새 기록은 체험판 기록이 된다
3. `scripts\start.ps1 -NoWindow`로 켠다
4. 터널: `cloudflared tunnel --url http://localhost:8501` → 찍히는 `https://….trycloudflare.com` 주소를 설문 메시지에 넣는다
   - Cloudflare Quick Tunnel: 계정 없이 무료. **켤 때마다 주소가 바뀌고**, 프로세스가 끝나면(PC 끄기·잠자기 포함) 주소도 끝난다. 동시 요청 200개까지, 가동 보장 없음
   - 체험 기간에는 PC를 켜 두고 절전을 끈다. 주소가 바뀌면 설문 안내를 고친다
5. 휴대폰(다른 네트워크)으로 주소 + 비밀번호로 들어가 시나리오 4개를 확인한다

## 끄기

- 터널 창을 닫고 `scripts\stop.ps1`. `.env`의 `BETA_PASSWORD`를 비우면 화면이 다시 설치형으로 돌아온다

## 체험 기록 보기

- 체험판 요청 기록(`data/gateway.db`)에는 가명화된 문장만 있다. 결과 정리는 `docs/survey.md`
