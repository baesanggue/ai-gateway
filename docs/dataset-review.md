# 기존 한국어 데이터셋 검토 (2026-10-27, #21)

면담에서 "기존 데이터셋 활용"을 제안받았다. 그래서 후보 데이터셋이 ① 진짜 한국어인지 ② 우리 판단 질문에 맞는 라벨이 있는지 ③ 학습에 써도 되는지를 공식 출처에서 확인했다. 후보는 Gemini가 추천한 것이라 하나씩 검증했다.

## 우리에게 필요한 라벨

판단 질문 6개: 민감정보(정규식이 놓친 이름·주소), 원본 값 필요, 기밀, 위험·인젝션, 난이도, 의도(FAQ / 업무 / 무관).
#5·#18 결과에서 Laya가 가장 약한 것은 **난이도·의도(라우팅)**, 가장 미묘한 것은 **원본 값 필요**다.

### 확인하며 알게 된 점

- **KLUE는 개인정보를 일부러 지웠다.** 논문에 따르면 PII가 든 예시는 제거했고, NER의 사람 이름(PS)은 검색엔진에 나오는 **공인**만 남겼다. 장소(LC)는 도시·도로 같은 지명이지 개인 주소가 아니다. 그래서 "LC가 있으면 개인정보"로 학습시키면 "부산 매장 영업시간?" 같은 문장도 민감정보로 잡는 **오탐**이 생긴다.
- **AI Hub 이용정책**(한국지능정보사회진흥원 데이터)
  - 인공지능 학습용으로는 영리·비영리 연구·개발에 쓸 수 있다.
  - 출처("한국지능정보사회진흥원의 사업결과")를 밝혀야 하고, 2차 저작물에도 밝혀야 한다.
  - **원본 데이터를 승인 없이 다른 사람에게 제공·양도·재배포하면 안 된다.** → 공개 저장소에 원본을 올릴 수 없다. 변환 스크립트와 통계만 올린다.
  - 국외 반출이나 국외 이용에는 별도 합의가 필요하다. 다운로드하려면 로그인과 신청이 필요하다.
- **Ko-UltraFeedback**은 번역체이고 내용도 일반 챗봇 질문(코딩·수학·글쓰기)이라 우리 도메인과 다르다. 원본 UltraFeedback에는 다른 LLM이 생성한 답변이 섞여 있어 출처 약관도 불분명하다.

## 결론

1. **법적으로는** KLUE와 AI Hub 두 데이터(판결서, 금융상담)를 학습에 쓸 수 있다. 각각 출처 표시가 필요하고, KLUE는 동일 조건이며, AI Hub는 원본 재배포가 금지된다. Ko-UltraFeedback은 쓰지 않는다.
2. **하지만 이 데이터만으로는 핵심 문제가 풀리지 않는다.** 실질적으로 도움이 되는 판단은 **민감정보(이름·주소)** 하나다. Laya가 가장 약한 **난이도·의도(라우팅)**와 가장 미묘한 **원본 값 필요**에 해당하는 라벨은 어느 데이터에도 없다.
3. 그래서 기존 데이터로 파인튜닝하면 "민감정보 판단을 다듬는" 데는 쓸 수 있다. 하지만 라우팅까지 가벼운 모델로 해결하려면 결국 우리 질문에 맞춘 라벨 데이터(합성 또는 직접 작성)가 따로 필요하다.
4. 면담 의견("가벼운 게 차별점이면 성능이 받쳐 주는 데까지로 활용 범위를 줄이는 것도 방법")과 연결하면, **가벼운 모델은 데이터와 성능이 받쳐 주는 판단(민감정보 등)만 맡기고, 라우팅은 다른 방법으로 하는 설계**도 선택지가 된다. → 10/28 100문장 비교 결과를 보고 결정한다.
