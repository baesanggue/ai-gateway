## 생성형 AI 활용 목적 및 개요 (3개 이상)
목적: 혼자서, 시험 기간을 뺀 약 3주 안에 "설치하면 바로 쓰는 AI 보안 게이트웨이"를 실제로 동작하고 수치로 검증된 수준까지 만드는 것. 이를 위해 구독형 AI 코딩 도구 Claude Code를 개발 팀원처럼 썼다.
1. 부족한 개발 인력 채우기: 게이트웨이·관리 화면·설치 스크립트·측정 도구를 혼자 만들기에는 일이 많았다. 코드와 자동 시험 작성은 AI에게 맡기고, 나는 설계·정책 결정과 결과 검토에 집중했다.
2. 처음 쓰는 기술을 빨리 익히기: 2026년 9월 이후 나온 도구(Ollaya, OpenAI Decisions)와 처음 다루는 분야(판단 모델 평가, 개인정보 인식 모델, 한글 hwpx 파일)를 AI에게 공식 문서부터 확인하게 하고 설명을 들으며 익혔다.
3. 숫자로 검증하기: "잘 되는 것 같다" 대신 근거를 보이려고 가상 테스트셋, 측정 실행기, 보안 검토를 AI와 함께 만들고 돌렸다.
4. 일하는 방식 정하기: 이슈마다 "AI가 계획 제안 → 내가 확인·수정 → AI가 구현·시험 → 내가 리뷰·머지 → 기록" 순서를 지켜, 무엇을 AI가 하고 무엇을 내가 정했는지 남겼다.

## 생성형 AI 활용 성과 (4개 이상)
1. 혼자서 일정보다 먼저 완성: 10/11~11/13 동안 커밋한 날 20일, PR 54개, 이슈 49개, 자동 시험 514개. 설치형 제품과 설문용 웹 체험판까지 만들었고, 마일스톤은 계획보다 이틀 앞섰다.
2. 결정은 내가 하고 근거를 남김: 설계 결정 29건과 AI 활용 기록 61줄. 판단을 "원본을 봐야 하는가"로 나눠 로컬·클라우드에 맡기는 구조, 업종 4개로 넓힌 테스트셋, "시험 데이터로 기준값을 다시 맞추지 않는다"는 원칙은 AI의 제안을 보고 내가 정했다.
3. AI가 만든 것을 AI와 함께 검증: 기능마다 AI 보안 검토를 받아 관리 기능 인증 누락, 비밀번호 잠금 우회 같은 문제를 머지 전에 고쳤다. AI가 만든 측정 도구로 가명화 99.5% 같은 수치를 얻었고, 그 측정에서 버그(주소 조사 중복)도 찾았다.
4. 새 도구를 빠르게 도입: 공개된 지 두 달이 안 된 판단 모델 후보 여러 개를 같은 테스트셋으로 비교해, 이틀 만에 판단 구조를 바꾸는 결정을 내렸다(10/26~10/27).
5. 개발 밖의 일도 함께: 발표 자료(저장소의 숫자를 읽어 만드는 스크립트), 30초 시연 영상 편집, 이 보고서 양식 채우기, 설문 문항 초안도 AI와 함께 만들었다.

## 생성형 AI 사용 후 느낀점 (2개 이상)
1. "무엇을 맡기고 무엇을 내가 정할지" 나누는 것이 실력이었다. 코드는 빨리 나왔지만 무엇을 막을지, 무엇이 범위 밖인지, 화면이 쓰기 편한지는 AI가 정해 주지 않았다. 화면은 직접 써 보고 세 번 고치게 했고, 개인정보 요청의 1/3이 막히는 불편도 직접 써 보며 알았다.
2. AI는 그럴듯하게 틀린다. AI가 추천한 데이터셋이 실제로는 없었고, AI가 쓴 기록 초안에 사실과 다른 확인 날짜가 들어간 적도 있다. 그래서 "출처를 보여 달라", "고친 코드를 지우면 시험이 실패하는지 보라", "비교할 대조군을 두라"를 요구하는 습관이 생겼다.
3. 빨리 만들수록 기록이 중요했다. 하루에도 여러 결정이 오가서, 결정 기록 덕에 예전 결정과 어긋난 라벨을 찾아 바로잡았다. AI 활용 기록 덕에 면담과 발표에서 "AI가 한 일"과 "내가 한 일"을 구분해 설명할 수 있었다.
