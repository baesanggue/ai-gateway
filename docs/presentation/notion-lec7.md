## 시스템 구조

(여기에 `architecture.png` 이미지)

기존 AI 서비스는 API 주소만 게이트웨이로 바꾼다. 요청은 회사 안의 게이트웨이에서 5단계를 거친다.

| 단계 | 담당 | 하는 일 |
|---|---|---|
| ① 가명화 | 코드 (정규식·사용자 사전) | 전화번호·이메일·주민번호·카드·계좌, 등록된 고객명을 `[고객1]`, `[전화번호1]` 같은 가명 토큰으로 치환 |
| ② 판단 | Laya (로컬 판단 모델) | 민감정보·기밀·원본 필요 여부, 난이도, 의도, 위험·인젝션을 판단하고 신뢰도를 함께 낸다 |
| ③ 라우팅 | 코드 (정책) | 보안 수준 + 판단 결과 + 신뢰도로 템플릿 / 저렴한 모델 / 고성능 모델 / 차단 중 선택 |
| ④ 답변 생성 | 외부 LLM API | 가명화된 텍스트만 받아 답변 생성 |
| ⑤ 복원 | 코드 | 답변 속 가명 토큰을 원래 값으로 되돌려 반환 |

**구성 요소**

| 구성 요소 | 기술 | 역할 |
|---|---|---|
| 게이트웨이 | FastAPI (Python) | OpenAI 호환 API(`/v1/chat/completions`) 제공 |
| 판단 엔진 | Ollaya + Laya 다국어 모델 | 로컬에서 판단만 수행 (가벼움) |
| LLM | 저렴한 API 모델 + 고성능 API 모델 | 답변 생성, 설정으로 교체 가능 |
| 요청 로그 | SQLite | 가명화된 텍스트·판단 결과·경로·비용만 저장 |
| 관리·데모 화면 | Streamlit | 비용 카운터, 단계별 판단 과정, 벤치마크 차트 |

**설계 원칙**
- 판단은 Laya, 생성은 LLM, 마스킹·계산은 코드
- 원본↔가명 대응표는 요청 처리 중 메모리에만 둔다. DB·로그·외부에 남기지 않는다
- 기본 구성에 무거운 로컬 LLM을 넣지 않는다. 완전 로컬 모드는 옵션
- 보안 수준(기본 / 엄격 / 완전 로컬) 하나만 고르면 동작이 바뀐다

## UI/UX 예시

(여기에 `ui-demo.png` 이미지 — 목업이며 수치는 실제 측정값이 아님)

**데모 화면 구성**
- 상단 비용 카운터: "전부 고성능 모델로 보냈을 때" vs "게이트웨이 사용" 누적 비용과 절감률
- 단계별 판단 과정: ① 감지된 민감정보 → ② Laya 판단·신뢰도 → ③ 선택 경로 → ④ 비용·지연
- 좌우 비교: 왼쪽 "외부 AI 서버로 나간 텍스트"(가명화), 오른쪽 "사용자가 받은 답변"(복원)

**관리 화면 메뉴**
| 메뉴 | 내용 |
|---|---|
| 요청 로그 | 요청별 가명화 텍스트, 판단 결과, 경로, 비용, 지연 |
| 통계 | 경로별 분포, 누적 절감액, 차단 건수 |
| 벤치마크 | 판단 정확도, 민감정보 탐지율, 비용 비교 차트 |
| 설정 | 보안 수준, 신뢰도 기준, 사용할 모델 |

**UX 원칙**
1. **설정은 하나**: 보안 수준만 고르면 된다
2. **투명하게**: 외부로 실제로 나간 텍스트를 그대로 보여줘서 "원본이 안 나갔다"를 눈으로 확인
3. **과정이 보이게**: 요청마다 AI가 어떻게 판단했고 왜 그 경로를 골랐는지 단계별로 표시
4. **도입이 쉽게**: 기존 서비스는 API 주소 한 줄만 바꾼다

## AI 활용방안

**1. 서비스 안에서 생성형 AI가 하는 일**

| 단계 | 사용하는 AI | 하는 일 | 규칙만으로 안 되는 이유 |
|---|---|---|---|
| 판단 | Laya (로컬) | 정규식이 놓친 이름·주소, 기밀 여부, 원본 값 필요 여부, 난이도, 의도, 위험·인젝션 판단 + 신뢰도 | "답하려면 실제 값이 필요한가", "이 요청이 어려운가"는 문맥을 이해해야 판단할 수 있다 |
| 답변 생성 | 외부 LLM | 가명 토큰이 든 요청으로 답변 생성. 난이도에 따라 저렴한 모델 / 고성능 모델 | 자연스러운 메일·안내문 작성 |
| 안내 문구 | LLM | 차단할 때 사유에 맞는 안내 문구 생성 (원문 없이 차단 사유만 전달) | 상황마다 다른 친절한 안내 |
| 품질 평가 | LLM | 벤치마크에서 원문 답변과 가명화 후 복원한 답변을 비교 채점 | 100문항을 사람이 다 채점하기 어렵다 (일부는 수동 확인) |
| (조건부) 개선 | Laya 파인튜닝 | 기본 모델의 한국어 정확도가 목표에 못 미치면 한국어 데이터로 파인튜닝 | |

**2. 신뢰도 활용**
- Laya는 판단마다 신뢰도를 낸다. 신뢰도가 낮으면 안전한 쪽(고성능 모델 또는 차단)으로 보낸다.
- 신뢰도 기준값은 벤치마크 결과(신뢰도 구간별 실제 정확도)를 보고 조정한다.

**3. 역할 분담 — AI가 약한 일은 코드가 맡는다**
- Laya는 글을 쓰거나 위치를 짚지 못한다 → 실제 치환·복원은 정규식·사전으로 코드가 수행
- 판단 모델은 숫자 계산·날짜 비교에 약하다 → 비용 계산 등은 코드가 수행

**4. 개발 과정에서의 AI 활용**
- AI 코딩 에이전트(Claude Code)에게 이슈 단위로 계획 → 구현 → 테스트를 맡기고, 계획 검토·설계 결정·코드 리뷰는 직접 한다
- 테스트셋 초안 100문항은 AI가 만들고, 라벨은 직접 하루 10행씩 검토한다
- AI에게 맡긴 일과 직접 결정한 일을 `docs/ai-log.md`에 날짜별로 기록한다
