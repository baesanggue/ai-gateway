# 30초 시연 대본 (#95, 11/17 발표 5번 장)

녹화 영상으로 넣는다(발표 중 네트워크·응답 지연 걱정이 없다). 입력은 직접 타이핑한다(자동 예시 버튼 없음).

## 녹화 전 준비 (체크리스트, #104)

1. **체험판 끄기**: `.env`의 `BETA_PASSWORD=` 줄 맨 앞에 `#`을 붙인다. 이 줄이 살아 있으면 `-Beta` 없이 켜도 화면이 체험판(비밀번호 화면, "남은 N회" 안내)으로 켜진다. 잊으면 `start.ps1`이 노란 글씨로 알린다. **녹화가 끝나면 `#`을 지운다**(체험판 운영에 필요)
2. 켜기: `powershell -ExecutionPolicy Bypass -File scripts\start.ps1` → 프로그램 창(1200×800)이 열린다. 이미 켜져 있었다면 `stop.ps1`로 끄고 다시 켠다(화면 서버는 다시 켜야 바뀐 설정·코드를 읽는다)
3. **미리 한 번 보내 두기**: 시연 화면에서 아래 문장들을 한 번씩 보내 본다. 그다음 프로그램 창에서 **F5**(새로고침)로 대화와 비용 카드를 비운다
4. **알림 끄기**: 작업 표시줄 시계 → 알림 → **방해 금지** 켜기. 메신저·메일 창은 닫는다
5. 녹화 도구: Windows 캡처 도구(시작 메뉴 → 캡처 도구 → 녹화 → 영역 선택) 또는 Xbox Game Bar(Win+Alt+R, 활성 창 녹화). 프로그램 창만 잡는다
6. 아래 세 문장을 메모장에 두고 복사해 붙인다. 손으로 치면 사과 메일 문장만 10초쯤 걸려 30초를 넘는다

```text
주문한 거 배송 언제 와요?
김민수 고객(010-1234-5678)에게 배송 지연 사과 메일 써줘
이 주민번호 900101-1234567로 고객 나이 계산해줘
```

### 미리 잰 결과 (11/12, 지금 버전으로 문장마다 5번)

| 문장 | 답이 오기까지 | 결과 |
|---|---|---|
| 배송 문의 | 바로 (0.1초 이내) | 5/5 정해 둔 답 |
| 사과 메일 | 평균 2.9초, 최대 3.9초 | 5/5 "김민수 고객님", 번호를 문의처로 쓴 답 0. 제목은 굵게 보인다 |
| 주민번호 | 0.3초 | 5/5 막고 안내 |

기다리는 시간이 길지 않아, 문장을 붙여 넣으면 자르지 않고도 30초 안에 들어갈 수 있다. 넘으면 사과 메일의 기다리는 부분만 자른다.

## 흐름 (30초)

| 시간 | 할 것 | 화면에서 보일 것 | 말할 것 (녹화 때 기준. 발표 때 말은 `talk-script.md` 5장) |
|---|---|---|---|
| 0~3초 | 왼쪽 메뉴 **시연** | 터미널 모양 챗봇, 비어 있는 처리 과정 | "기존 챗봇의 API 주소만 바꾼 상태입니다" |
| 3~8초 | `주문한 거 배송 언제 와요?` Enter | 정해 둔 답이 바로. 처리 과정: 로컬·클라우드 판단 건너뜀, 경로 '템플릿' | "배송 문의는 LLM 없이 정해 둔 답, 비용 0" |
| 8~19초 | `김민수 고객(010-1234-5678)에게 배송 지연 사과 메일 써줘` Enter | 아래 왼쪽 **외부로 나간 텍스트**에 노란 `[고객1]`·`[전화번호1]`, 오른쪽 **받은 답변**에 김민수 | "밖으로는 [고객1]만 나가고, 받은 답변에는 김민수가 돌아옵니다" |
| 19~26초 | `이 주민번호 900101-1234567로 고객 나이 계산해줘` Enter | 빨간 안내문, 처리 과정 '클라우드 판단: 원본 필요 → 막음' | "실제 값이 필요한 요청은 밖으로 보내지 않고 안내합니다" |
| 26~30초 | 위 **비용 카드**를 가리킨다(마우스) | 기존 방식 vs 게이트웨이, 절감 % | "기존 방식보다 비용이 이만큼 줄었습니다" |

- 두 번째 요청은 답이 오기까지 몇 초 걸린다. 영상 편집(Windows 기본 앱 Clipchamp)으로 기다리는 부분을 잘라 30초에 맞춘다
- 이름·번호·주민번호는 모두 가상 값(시연용 사전, 확인 숫자가 틀린 주민번호 형식)이다
