## 1. 문제 (30초)

**슬라이드**: 문제 3개를 한 줄씩

**말할 것**
- 기업이 생성형 AI를 쓰면 고객 이름·전화번호·사내 기밀이 그대로 외부 AI 서버로 간다.
- "배송 언제 와요?" 같은 쉬운 질문도 비싼 고성능 모델로 보내서 돈과 시간이 샌다.
- 이걸 막는 로컬 AI 도구는 무겁고 설정이 어려워 중소기업은 도입하기 힘들다.

## 2. 해결: 한 줄 소개 (30초)

**슬라이드**: "API 주소 한 줄만 바꾸면, 개인정보 보호와 토큰 절약이 붙는 로컬 게이트웨이"

**말할 것**
- 기존 AI 서비스와 외부 AI 서버 사이에 끼우는 중간 관문이다.
- 강점 3가지
  - 보안: 민감정보 원본은 밖으로 나가지 않는다. 판단도 로컬에서 한다.
  - 절약: 요청을 분류해서 필요한 만큼의 모델에만 보낸다.
  - 간편: 설치 한 번, 설정은 보안 수준 하나만 고른다.

## 3. 구조 (60초)

**슬라이드**: 흐름도

```
기존 AI 서비스 → ① 가명화(코드) → ② 판단(Laya, 로컬) → ③ 경로 선택 → ④ 답변 생성(LLM) → ⑤ 복원(코드) → 사용자
                                                       ├ 템플릿 응답 (LLM 없음)
                                                       ├ 저렴한 모델
                                                       ├ 고성능 모델
                                                       └ 차단 + 안내
```

**말할 것**
- 핵심 원칙: **판단은 Laya, 생성은 LLM, 마스킹은 코드.**
- Laya는 "예/아니오, 몇 점, 어느 쪽" 같은 판단만 하는 가벼운 로컬 모델이다. 글을 쓰지 않으니 무거운 로컬 LLM이 필요 없다.
- 실제 치환과 복원은 정규식·사전으로 코드가 정확하게 한다.
- 원본과 가명의 대응표는 요청 처리 중 메모리에만 둔다. 로그에는 가명화된 텍스트만 남긴다.

## 4. 핵심 기능과 생성형 AI의 역할 (60초)

**슬라이드**: 아래 표

| 기능 | 생성형 AI의 역할 |
|---|---|
| 민감정보 가명화·복원 | Laya: 정규식이 놓친 이름·주소, 기밀 수준, 원본 값 필요 여부 판단 / LLM: 가명 토큰이 든 요청으로 답변 생성 |
| 요청 판단·자동 라우팅 | Laya: 난이도·의도 판단과 신뢰도 / LLM: 선택된 모델이 답변 생성 |
| 위험·무관·인젝션 차단 | Laya: 위험·무관·프롬프트 인젝션 판단 / LLM: 차단 사유에 맞는 안내 문구 생성 (원문 없이 사유만 전달) |
| 비용·판단 과정 화면 + 벤치마크 | Laya 판단·신뢰도를 단계별로 표시 / LLM: 원문 답변 vs 가명화 후 복원 답변 품질 채점 |

**말할 것**
- 모든 기능에서 역할이 나뉜다. Laya는 판단, LLM은 생성.
- 보안 수준은 기본 / 엄격 / 완전 로컬(옵션) 중 하나만 고르면 동작이 바뀐다.

## 예상 질문과 답변 메모

**Q1. Spring Boot 경험이 있는데 왜 Python으로 바꿨나?**
판단 모델 SDK, 벤치마크, 파인튜닝 도구가 전부 Python이다. 게이트웨이만 Java로 하면 두 언어를 오가야 한다. 1인·4주 개발이라 한 언어로 통일하는 이득이 더 크다고 판단했다.

**Q2. 로컬 LLM을 쓰면 더 안전하지 않나?**
가장 안전하지만 GPU와 메모리가 필요해서 "간편함"을 잃는다. 기본은 가벼운 판단 모델만 쓰고, 정말 민감한 환경을 위해 완전 로컬 모드를 옵션으로 둔다.

**Q3. Laya가 한국어를 제대로 판단하나?**
아직 검증 전이다. 10/26에 한국어 문장으로 먼저 측정하고, 100문항 테스트셋으로 벤치마크한다. 부족하면 신뢰도 임계값으로 안전하게 처리하고, 이후 파인튜닝한다.

**Q4. 가명화해도 LLM이 답을 잘 만드나?**
같은 요청을 원문으로 보낸 답변과 가명화 후 복원한 답변을 LLM 채점과 일부 수동 확인으로 비교해서 수치로 보여줄 예정이다.

**Q5. 판단이 틀려서 민감정보가 새면?**
Laya 판단과 별개로 정규식·사전 가명화가 항상 먼저 실행된다. Laya는 그 위에 한 겹을 더하는 구조다. 엄격 수준에서는 의심만 돼도 차단한다. "놓친 개인정보 비율"을 핵심 지표로 측정한다.
