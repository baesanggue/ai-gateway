# 업종 프리셋 (`config/presets/`, D22, #38)

게이트웨이는 업종과 무관한 범용 제품이다(D13). 업종마다 달라지는 설정만 프리셋으로 묶어 **`config.yaml` 한 줄로 바꾼다.** 11/03 면담 의견("환경에 따라 설정으로 바꾸는 기능")을 반영했다.

```yaml
# config.yaml
preset: shop        # shop(쇼핑몰, 주 시연) | medical(병원) | school(학교)
```

## 프리셋에 들어 있는 것
| 항목 | shop | medical | school |
|---|---|---|---|
| FAQ와 정해 둔 답 | 배송·반품·교환·주문 취소·결제·상담 시간 | 진료 시간·예약·주차·서류 발급·검사 결과 | 학사 일정·성적·휴학/복학·장학금·증명서 |
| 회사별 식별번호 (#38) | 회원번호 `M` + 8자리 → `[회원번호1]` | 차트번호 `C` + 8자리 → `[차트번호1]` | 학번 `20` + 6자리 → `[학번1]` |
| 시연용 가상 사전 | `고객`, `직원`, `사내` | `환자`, `의료진` | `학생`, `교직원` |
| 테스트셋 근거 | 100행 (T) | 30행 (M) | 없음 (설정 예시) |

- 나머지(판단 엔진, LLM, 보안 수준, 차단 안내문)는 업종과 무관해서 `config.yaml`에 그대로 둔다.
- **`config.yaml`에 직접 적은 값이 프리셋보다 우선한다.** dict는 안쪽까지 합치고, 목록(FAQ 항목, 식별번호)은 통째로 바뀐다.
- 없는 프리셋 이름이면 시작하지 않고, 쓸 수 있는 프리셋을 알려 준다.

## 회사별 식별번호
```yaml
masking:
  custom_patterns:
    - kind: 차트번호                                   # 토큰 이름 → [차트번호1]
      pattern: "(?<![A-Za-z0-9])C[0-9]{8}(?![0-9])"     # 숫자는 [0-9]로 (\d는 모든 문자권 숫자를 받는다)
```
- 같은 번호가 회사 안에서는 사람을 찾는 열쇠이고 LLM 회사에게는 의미 없는 숫자다. 회사마다 정답이 달라 판단 모델 하나에 가르칠 수 없으므로 회사가 등록한다(D19).
- 사용자 사전 다음, 기본 정규식보다 먼저 본다(더 구체적이다). 가명화·복원·마지막 검사(`pii_unmasked`)에 똑같이 적용된다. 동그라미 글자 `Ⓒ12345678`처럼 정규화로 못 가린 표기는 차단하고 로그에도 남기지 않는다.
- 시작할 때 검사한다. 잘못된 정규식, 토큰 이름으로 쓸 수 없는 종류, **반복 안에 반복**이 있는 정규식(`(C[0-9]+)+`)은 받지 않는다. 마지막 것은 긴 입력에서 처리 시간이 폭증하기 때문이다(#11 보안 검토).

## 시연용 사전 바꾸기
사용자 사전은 업종마다 다르다. 프리셋을 바꿔 시연할 때는 그 프리셋의 시연용 사전을 사용자 사전 자리로 복사한다(D21).
```
copy config\presets\medical.dictionary.example.txt private\user_dictionary.txt
```

## 새 업종 추가
1. `config/presets/<이름>.yaml`을 만든다. `shop.yaml`을 복사해 FAQ·식별번호·시연용 사전 경로를 바꾼다.
2. `config/presets/<이름>.dictionary.example.txt`에 가상 이름을 `종류,값`으로 적는다.
3. `config.yaml`에서 `preset: <이름>`으로 바꾼다. 코드는 고치지 않는다.
