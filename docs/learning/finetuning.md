# 판단 모델 파인튜닝: 무엇을 했고 무엇을 배웠나 (#20~#22, D15)

처음 보는 사람에게 설명하는 정리다. 결과 수치는 `bench/results/finetune-2026-11-07/summary.md`, 결정은 `docs/decisions.md` D15에 있다.

## 1. 왜 했나

게이트웨이는 판단을 둘로 나눈다(D12).
- 원본을 봐야 하는 판단(기밀)은 로컬 소형 모델 `gliclass`가 한다.
- 가명화된 문장으로 충분한 판단(원본 필요·위험·난이도·의도)은 클라우드 OpenAI Decisions가 한다.

"판단까지 전부 로컬"이 되면 가명화된 문장조차 밖으로 나가지 않는다. 그래서 다국어 판단 모델 `laya-multilingual`을 한국어 업무 문장으로 다시 학습(파인튜닝)해, **모델 하나가 판단 5개를 다 할 수 있는지** 같은 시험지로 비교했다. 이기면 "완전 로컬" 옵션이 되고, 지면 지금 구성을 택한 근거가 된다.

## 2. 파인튜닝이란

이미 학습된 모델에서 출발해, 우리 문제의 예제로 조금 더 학습시키는 것이다. 처음부터 학습하는 것보다 데이터가 훨씬 적게 든다(여기서는 2,977줄). Laya는 "문장 + 질문 → 답별 확률"을 내는 판단 전용 모델이라, 학습 예제도 `{문장, 질문들, 정답}` 한 줄이다.

## 3. 데이터를 어떻게 만들었나 (#21)

| 단계 | 하는 일 | 이유 |
|---|---|---|
| 범주 정하기 | 12개 범주(FAQ, 이용 문의, 간단한 업무, 복잡한 업무, 가릴 수 있는 개인정보, 원본 필요, 기밀, 위험, …)와 범주별 정답표 | 정답을 사람이 한 줄씩 붙이지 않고 **범주가 정한다**. 범주로 확실히 정할 수 없는 질문은 비워 둔다(학습에서 빠짐) |
| 문장 생성 | 로컬 모델 `gemma4:12b`가 범주·업종·말투마다 10문장씩 | 클라우드 모델 출력은 약관상 학습 데이터로 쓰지 않는다 |
| 개인정보 채우기 | 생성 모델은 `{이름}` `{전화번호}` 자리표시만 쓰고, 코드가 가상 값을 채운다 | 개인정보 정답을 코드가 안다. 가상 값은 형식 검사(생년·성별 자리, 카드 Luhn)를 통과한다 |
| 가명화본 | 개인정보 문장은 `[고객1]`·`[이름1]` 토큰으로 바꾼 줄도 만든다 | 게이트웨이가 실제로 판단 모델에 보내는 모양이다 |
| 자동 검사 | 형식, 한국어, 이름을 직접 쓴 문장, 중복, **테스트셋과 비슷한 문장** 빼기 | 테스트셋이 학습에 새면 시험이 무의미해진다 |
| 표본 검토 | 무작위 50줄을 사람과 Claude가 따로 읽고 비교, 오류 5% 이하 | 범주로 붙인 정답이 실제 문장과 맞는지 확인 |

검토에서 배운 것: 오류 두 줄(#37·#49)이 같은 원인이었다. 전체를 세 보니 "이용 문의" 범주 문장의 31%가 실제로는 FAQ였다. 생성 모델에 "이걸 만들어라"라고 해도 비슷한 다른 것이 섞여 나온다. 그런 줄은 의도 정답을 비웠다.

## 4. 학습 (#22)

- `laya.train.finetune(데이터, 시작 모델, 저장 위치, 설정, device="cuda")` 한 번이다. 이 PC의 RTX 4080 SUPER에서 12.9분, GPU 메모리 6GB가 들었다.
- **온도 보정(temperature calibration)**: 학습이 끝나면 따로 떼어 둔 400문항으로, 모델이 말하는 확률이 실제 정답률과 맞도록 출력을 조정한다. "90%라고 하면 실제로 90% 맞게"가 목표다.
- 학습 중 평가는 10/31에 만든 시범 데이터로 했다(테스트셋이 아님). 학습 데이터와 거의 같은 문장은 미리 뺐다.

## 5. 평가를 어떻게 공정하게 했나

- **테스트셋 190행은 학습에도, 기준값 고르기에도 쓰지 않았다.** 마지막에 한 번만 쟀다.
- 기준값("확률이 몇 이상이면 예")은 시범 데이터에서 골랐다. 테스트셋에서 고르면 그 테스트셋에 맞춘 점수가 된다.
- 지금 구성(A)과 **같은 입력**(#46과 같은 가명화 문장)과 **같은 지표**(D14 목표)로 비교했다. A의 기준값은 M0에서 테스트셋으로 정한 값이라 A에 조금 유리하다.

## 6. 결과

| 판단 (목표) | 지금 구성 | 파인튜닝한 Laya | 파인튜닝 전 |
|---|---|---|---|
| 원본 필요 (≥ 85%, 오탐 ≤ 2%) | 100%, 1% | **100%, 1%** ✅ | 94%, 22% |
| 난이도 (≥ 85%) | 96% | **86%** ✅ | 46% |
| 의도 (≥ 90%) | 96% | **92%** ✅ | 55% |
| 기밀 (≥ 90%) | 92% | **62%** ❌ | 85% (오탐 89%) |
| 위험 (≥ 95%, 오탐 ≤ 1%) | 100%, 0% | **85%**, 0% ❌ | 92%, 66% |

파인튜닝 효과는 컸다. 하지만 보안 판단 두 개가 목표에 못 미쳐 **지금 구성을 유지**한다.

## 7. 배운 점

1. **같은 생성기로 만든 평가는 성적을 부풀린다.** 시범 데이터에서는 99%였지만 사람이 쓴 테스트셋에서는 기밀이 62%였다. 학습·평가 데이터가 같은 모델에서 나오면, 그 모델의 문장 습관까지 같이 맞히는 것이다.
2. **모델은 모르는 것을 모른다고 하지 않았다.** 놓친 기밀 5개와 위험 2개는 모두 학습 주제 밖이었고(공공·의료 기밀, 인젝션이 아닌 불법 요청), 모델은 이 문장들에 확률 0을 줬다. 테스트셋 확률의 99%가 0.01 미만이거나 0.99 초과였다. 온도 보정은 보정용 문항이 학습 데이터와 같은 분포라 고칠 것이 없었다("정확도 100%라 그대로 둠" 경고).
3. **범주로 정답을 붙이면 범주의 넓이가 곧 모델의 넓이다.** "기밀 = 실적·인수합병·연봉·단가·신제품"으로 만들면 모델도 딱 그만큼만 기밀로 안다.
4. **놓친 문장을 본 뒤에는 그 테스트셋으로 다시 판정할 수 없다.** 다음 학습에서 놓친 유형을 넣으면 점수는 오르겠지만, 그건 시험 문제를 보고 공부한 것이다. 다음 판정은 새로 쓴 평가 문장으로 해야 한다.

## 8. 다시 한다면

- 기밀·위험의 주제 목록을 업종별 정의에서 넓힌다: 공공(개발 후보지, 감사·징계), 의료(운영 계획, 사고 보고), 금융(내부 금리), 불법 요청(조작·불법 구매).
- 생성 모델을 두 개 이상 섞어 문장 습관이 한쪽으로 쏠리지 않게 한다(라이선스 확인 필요).
- 사람이 새로 쓴 평가 문장(업종마다 수십 개)을 먼저 만들고, 그것으로 판정한다.
