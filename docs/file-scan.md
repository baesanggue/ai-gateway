# 파일 검사 (`gateway/files/`, #50)

PDF·워드·엑셀 속 개인정보를 찾아 안내하고, AI에 붙여넣어도 되는 **가명화된 텍스트**를 만든다. 11/03 면담 의견을 반영했다: 파일 속 개인정보를 판단해 안내문을 띄우는 기능이 있으면 좋다.

**생성형 AI의 역할**: 없다. 글자 뽑기와 가명화는 코드가 한다(설계 결정 1번). 판단 모델을 쓰지 않는 이유는 긴 문서가 판단 모델이 읽을 수 있는 길이를 넘기 때문이다(D19, #39). 파일은 이 PC 밖으로 나가지 않는다.

## 사용
```bash
uv run python -m gateway.files 고객명단.xlsx --masked-out 가명화.txt
```
```
개인정보 4개를 찾았습니다: 고객 2개, 전화번호 1개, 회원번호 1개. 위치: '고객' 시트 A2, '고객' 시트 B2, …
이 파일을 그대로 외부 AI에 올리지 말고, 가명화된 텍스트를 쓰세요.
```
- API: `POST /v1/files/scan` `{"filename": "고객명단.xlsx", "content_base64": "…"}`
  - 응답: `has_pii`, `summary`, `counts`, `findings`(위치별 종류·개수), `unmasked`, `masked_text`
  - 게이트웨이 키 규칙은 채팅과 같다(D20).
- 시연 화면의 파일 끌어다 놓기는 M4에서 이 API를 부른다.

## 무엇을 읽나
| 형식 | 읽는 곳 | 위치 표시 |
|---|---|---|
| PDF | 글자 층 | `3쪽` |
| DOCX | 문단, 표, 머리글·바닥글 | `2번째 문단`, `표 1 1행`, `머리글(구역 1)` |
| XLSX | 셀 값(수식은 계산된 값) | `'고객' 시트 B2` |
| TXT·CSV | 줄 (UTF-8, 한국어 엑셀의 CP949 CSV) | `2번째 줄` |

- 검사 규칙은 채팅과 같다: 사용자 사전 → 회사별 식별번호(업종 프리셋) → 정규식 → 마지막 검사.
- 파일 전체를 한 번에 가명화해서, 같은 값은 어느 칸에 있든 같은 토큰이 된다.
- **결과에는 값을 넣지 않는다.** 종류, 개수, 위치, 가명화된 텍스트만 준다. 복원 대응표도 돌려주지 않는다. 원본은 사용자 파일에 있다.

## 읽지 못하는 파일
| 경우 | 안내 (`code`) |
|---|---|
| 스캔 PDF·이미지만 든 파일 | 글자를 읽을 수 없음 (`no_text`). OCR은 범위 밖이다 |
| 암호 PDF | `encrypted` |
| 지원하지 않는 형식(hwp 등), 이름만 바꾼 파일 | `unsupported`, `unreadable` |

## 안전장치
- 크기 상한 10MB. 파일 앞부분(`%PDF`, `PK`)으로 형식을 확인하고 깊이 읽는다.
- docx·xlsx는 zip이다. **압축 폭탄**을 막으려고 풀린 크기 합(100MB), 압축률(100배), 항목 수를 파싱 전에 본다.
- XML 외부 엔티티를 풀지 않는다. python-docx는 `resolve_entities=False`, openpyxl은 defusedxml을 쓴다(없으면 엑셀을 읽지 않는다).
- PDF 안의 압축된 데이터도 하나를 풀었을 때 20MB까지만 푼다(pypdf 설정, 검사 함수 안에서만 적용). 넘으면 `zip_bomb`.
- 쪽(500)·셀(20만)·글자(200만)·PDF 시간(30초) 상한은 **읽는 도중에** 확인한다. 다 읽은 뒤에 세면 그 전에 시간·메모리가 먼저 든다.
  - docx·xlsx 안 XML은 파서보다 먼저, 트리를 만들지 않고 훑어서 요소 수(150만)·셀 수·한 행의 칸 수(XFD열 16,384)를 센다. 엑셀 파서는 한 행을 통째로 메모리에 올린 뒤 넘겨 주기 때문이다. 이때 엔티티 선언이 있거나 훑지 못한 XML이 있으면 읽지 않는다(`unreadable`).
    - 훑는 대상: 이름이 `.xml`·`.rels`인 부분, `[Content_Types].xml`에 XML로 적힌 부분, 앞부분이 XML처럼 보이는 부분(BOM 없는 UTF-16·32, EBCDIC 포함). 파서는 읽는데 검사는 건너뛰는 부분이 없게 넓게 잡는다. 이미지·글꼴·인쇄 설정 같은 이진 부분만 건너뛴다.
  - 엑셀은 값이 없는 칸과 빈 행도 센다. 파일에 적힌 시트 크기(`A1:XFD1048576` 같은 값)는 믿지 않고 실제로 있는 칸만 돈다.
  - PDF는 pypdf가 연산자마다 부르는 함수로 **한 쪽 안에서도** 시간·글자를 본다. 양식 객체(XObject)를 수백 번 불러 쓰는 쪽도 중간에 멈춘다. pypdf가 양식 안에서 난 예외를 삼키지만, 바깥 쪽의 다음 연산자에서 다시 걸린다.
    - 글자는 연산자(`Tj`·`TJ`·`'`·`"`)가 실행되기 **전에** 실린 문자열 길이로 센다. pypdf는 글자를 모아 두었다가 위치가 바뀔 때에야 넘겨 주기 때문이다.
- 남은 위험: 내용 스트림 하나를 해석하는 동안(연산자를 넘겨 주기 전)은 pypdf 자체 상한(해석량 200만)에 맡긴다. 글꼴의 글자 대응표(ToUnicode)가 바이트 하나를 긴 글자열로 바꾸게 만든 PDF는 연산자 하나 안에서 어림값보다 많이 늘어날 수 있다. 메모리 상한은 없다(Windows). 완전히 막으려면 별도 프로세스에서 시간·메모리 제한을 걸고 읽어야 한다. 게이트웨이가 기본으로 이 PC 안에서만 요청을 받으므로(D20) 지금은 이 정도로 둔다.
